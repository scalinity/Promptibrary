# V2 candidates

Items surfaced during V1 implementation that are out of V1 scope but worth tracking for a V2 pass.

- Bundle Boska Variable and Switzer Variable locally instead of loading from Fontshare CDN.
- Variable-ref constraint quoting (SCA-610): the spec §5 grammar splits constraint values on bare `,` and `=` with no escape, so a `pattern` constraint can't contain those chars directly. Workaround today is to author patterns without them or move the pattern to the YAML `variables[].pattern` field. V2 should introduce a quoting mechanism (backslash-escape or single-quoted values) and update the EBNF to match.
- Regex cache LRU bound (SCA-625): `variables::regex_cache` is unbounded process-wide. Bound via an LRU cache (cap ~256) once we have data on real-world pattern counts. Today's working-set is small enough that this is V2-grade work.
- UNIQUE constraint on `prompts.slug` (SCA-626): W-1 / SCA-589 closed the slug-collision race with an AppServices mutex. V2 should land a schema migration adding `UNIQUE(slug)` plus an INSERT … ON CONFLICT(slug) retry-with-bumped-suffix loop, then drop the mutex. The mutex is correct for V1 single-user; the schema-level fix is the long-term answer.
- **Apple Developer ID signing + notarization (SCA-729 / L5).** V1 ships intentionally unsigned by Apple's authority. Distributed builds need an Apple Developer Program enrollment ($99/yr), a Developer ID Application certificate, `APPLE_CERTIFICATE` + `APPLE_CERTIFICATE_PASSWORD` + `APPLE_ID` + `APPLE_PASSWORD` + `APPLE_TEAM_ID` secrets in GitHub Actions, and `xcrun notarytool submit --wait` plus stapling in the release workflow. Document the rotation/expiry cadence too — Developer ID certs expire on a five-year clock. V1's Tauri signer signature on update bundles is unchanged; this is purely about Gatekeeper's first-launch UX.
- **Enable `fastembed` + real bge-small-en-v1.5 model (SCA-784).** The semantic-search architecture is done — `EmbeddingService` trait, `MockEmbeddingService` (deterministic hash-based vectors for tests), `prompt_embeddings` storage + cosine search, hybrid path that consumes the semantic component, semantic-only mode that returns cosine-ranked results. What remains for V2: (1) uncomment `fastembed = "5.13"` in `src-tauri/Cargo.toml` and absorb the ORT native-runtime compile cost; (2) implement `FastembedService` that lazy-loads bge-small from `<app_data_dir>/embeddings/bge-small-en-v1.5/`; (3) build-time SHA-256 manifest with fail-closed hash verification; (4) first-run download from HuggingFace (~130 MB) with `index://progress` events; (5) reindex queue (concurrency 1, idle scheduler) that backfills missing/stale rows; (6) flip `AppServices::embedding_service` from `MockEmbeddingService` to the real impl in production builds. Mock impl keeps the test suite green either way.
- **`prompt_stats` / `tag_stats` incremental cache (SCA-729 / L5).** `prompt_aggregates(db)` currently computes on demand via a single GROUP BY on `runs`. For V1 dataset sizes (~hundreds of runs) this is fast enough. V2 should land the spec §10 cached tables and incrementally maintain them on every run-status transition so the library row reads are bounded by O(prompts) regardless of total run history.
- **L3 launch pipeline implementation (surfaced during L5 deferrals).** L3 was tagged `layer-3-complete` but every file under `src-tauri/src/launch/` is a 3-line stub, `portable-pty` is commented out in Cargo.toml, and `commands::launches::*` are all `not_yet_implemented_stub`. `index::runs_repo::{insert_run, update_run_status, complete_run}` ships (SCA-785) — the storage surface is ready — but no production caller exists. V2 (or an L3 amend) needs: (1) uncomment `portable-pty = "=0.9.0"`; (2) implement `launch::{pty_session, prompt_injector, signals, transcript_writer, pty_pool, process_probe, claude_cli}` per `Prompts/L3.md`; (3) wire `commands::launches::{start_launch, stop_run, send_terminal_input, resize_terminal}`; (4) hook `runs_repo` writes + `telemetry_repo::record_event` at the three lifecycle moments. Until this lands, the spec §1 acceptance criterion *launch 3× → library row shows launch_count: 3* fails.
- **Hybrid search 3-query → 1 CTE (SCA-760 / L5 deferred perf).** `commands/search::hybrid` runs three sequential round-trips per query: FTS5 → `fetch_prompt_meta` → `fetch_usage_stats`. At V1 scale (hundreds of prompts, hundreds of runs) this is fast on a hot SQLite pool; at scale the keystroke-loop latency adds up. V2 candidate: fold all three into one CTE-based query returning `(prompt_id, title, bm25_rank, launch_count, last_used_at)` so the hybrid path is one round-trip per query.
