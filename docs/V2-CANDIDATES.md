# V2 candidates

Items surfaced during V1 implementation that are out of V1 scope but worth tracking for a V2 pass.

- Bundle Outfit Variable locally instead of loading from Google Fonts CDN. (Superseded prior Boska/Switzer Fontshare entry — the aesthetic pivot in SCA-866 swapped to Outfit + JetBrains Mono.)
- Variable-ref constraint quoting (SCA-610): the spec §5 grammar splits constraint values on bare `,` and `=` with no escape, so a `pattern` constraint can't contain those chars directly. Workaround today is to author patterns without them or move the pattern to the YAML `variables[].pattern` field. V2 should introduce a quoting mechanism (backslash-escape or single-quoted values) and update the EBNF to match.
- Regex cache LRU bound (SCA-625): `variables::regex_cache` is unbounded process-wide. Bound via an LRU cache (cap ~256) once we have data on real-world pattern counts. Today's working-set is small enough that this is V2-grade work.
- UNIQUE constraint on `prompts.slug` (SCA-626): W-1 / SCA-589 closed the slug-collision race with an AppServices mutex. V2 should land a schema migration adding `UNIQUE(slug)` plus an INSERT … ON CONFLICT(slug) retry-with-bumped-suffix loop, then drop the mutex. The mutex is correct for V1 single-user; the schema-level fix is the long-term answer.
- **Apple Developer ID signing + notarization (SCA-729 / L5).** V1 ships intentionally unsigned by Apple's authority. Distributed builds need an Apple Developer Program enrollment ($99/yr), a Developer ID Application certificate, `APPLE_CERTIFICATE` + `APPLE_CERTIFICATE_PASSWORD` + `APPLE_ID` + `APPLE_PASSWORD` + `APPLE_TEAM_ID` secrets in GitHub Actions, and `xcrun notarytool submit --wait` plus stapling in the release workflow. Document the rotation/expiry cadence too — Developer ID certs expire on a five-year clock. V1's Tauri signer signature on update bundles is unchanged; this is purely about Gatekeeper's first-launch UX.
- **Re-enable `fastembed` for real semantic search — V2 follow-ups (SCA-808 partially landed).** What now ships: optional `fastembed = "5.13"` cargo dep behind the `fastembed` feature flag; `FastembedService` impl using `TextEmbedding::try_new(InitOptions::new(BGESmallENV15).with_cache_dir(...))`; `AppServices::new` swaps `MockEmbeddingService` for `FastembedService` when the feature is enabled (with graceful fallback to mock on init failure). Build path: `cargo build --features fastembed` and `cargo tauri build --features fastembed`. What's still V2: (a) build-time SHA-256 manifest baked into the binary + fail-closed hash verification per spec §9 (fastembed currently relies on upstream Hugging Face SHA validation); (b) `index://progress` Tauri events for first-run download UI; (c) the reindex queue that backfills missing/stale embeddings at concurrency 1 with an idle scheduler.
- **L3 launch pipeline — comprehensive scope (post-SCA-785 audit).** The runs_repo storage surface ships (SCA-785 + 5 unit tests) but the L3 launch pipeline itself is unimplemented. Spec §7 + CLAUDE.md *Launch pipeline (L3)* invariants enumerate the missing pieces:
  1. Uncomment `portable-pty = "=0.9.0"` in `src-tauri/Cargo.toml` (pinned per spec §2).
  2. `launch::claude_cli::resolve_claude_path()` — runs `"$SHELL" -lc 'command -v claude'`, caches the result; re-runs on Settings → Run diagnostics.
  3. `launch::pty_session` — `portable_pty::CommandBuilder::new(claude_path)` (no shell wrap), `cmd.env_remove("COLUMNS"); cmd.env_remove("LINES");` (env scrub), no `ANTHROPIC_API_KEY` pass-through; `pty_pair.slave.spawn_command(cmd)`.
  4. `launch::prompt_injector` — event-driven bracketed paste (`ESC[200~ <resolved> ESC[201~ \r`) AFTER the first PTY output chunk fires, not after a fixed sleep.
  5. `launch::signals` — graceful stop: SIGINT → 5s → SIGINT → 5s → SIGTERM → 3s → SIGKILL; force stop: SIGTERM → 1s → SIGKILL. Signals go DIRECTLY to the claude child PID (no shell intermediary).
  6. `launch::transcript_writer` — copy stdout to `<vault>/promptibrary/runs/YYYY/MM/<run_id>.md` with ANSI normalisation: preserve 24-bit color SGR, preserve OSC 8 hyperlinks, strip OSC 52 clipboard + OSC 0/1/2 title sequences.
  7. `launch::pty_pool` — `Arc<Mutex<HashMap<RunId, PtySession>>>` on `AppServices`, with the active-run cap from `LaunchDefaults`.
  8. `launch::process_probe` — wraps `claude --version` for the diagnostics card.
  9. Runtime directory layout — `~/Library/Application Support/promptibrary/runtime/runs/<run_id>/` containing `prompt.txt`, `claude-settings.json` (merged allow/deny rules), `mcp.json` (merged MCP config paths).
  10. Wire `commands::launches::{start_launch, stop_run, send_terminal_input, resize_terminal}` against the above.
  11. Hook `runs_repo::{insert_run, update_run_status, complete_run}` at the §10 *Run record lifecycle* moments (PTY spawn → FirstOutput → Finished/Errored).
  12. Hook `telemetry_repo::record_event` for `launch_created`, `launch_started`, `first_output`, `launch_stopped`, `launch_finished`, `transcript_spooled`, `error` at the same moments.
  13. The §15 *Fake Claude launch* integration test — exercises the whole pipeline without depending on a real claude binary.
  14. Frontend `commands::launches` IPC wrappers in `src/shared/api/ipc.ts` + matching mock entries.
  Without all 14, spec §1 criteria 5 and 6 cannot pass. Decision point: amend `layer-3-complete` with a dedicated L3-reconciliation session OR ship V1 with launch disabled and a clear in-UI banner.
- **`prompt_stats` / `tag_stats` incremental cache (SCA-729 / L5).** `prompt_aggregates(db)` currently computes on demand via a single GROUP BY on `runs`. For V1 dataset sizes (~hundreds of runs) this is fast enough. V2 should land the spec §10 cached tables and incrementally maintain them on every run-status transition so the library row reads are bounded by O(prompts) regardless of total run history.
- **Hybrid search 3-query → 1 CTE (SCA-760 / L5 deferred perf).** `commands/search::hybrid` runs three sequential round-trips per query: FTS5 → `fetch_prompt_meta` → `fetch_usage_stats`. At V1 scale (hundreds of prompts, hundreds of runs) this is fast on a hot SQLite pool; at scale the keystroke-loop latency adds up. V2 candidate: fold all three into one CTE-based query returning `(prompt_id, title, bm25_rank, launch_count, last_used_at)` so the hybrid path is one round-trip per query.
